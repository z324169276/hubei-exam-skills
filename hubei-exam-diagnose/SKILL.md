# 湖北技能高考学情诊断师

把一份或一批答卷，换算成**知识点级**的掌握度，再沿依赖边回溯出"真正的病根"，而不是只列出"哪道题错了"。

开始前先读：
- [references/graph.md](references/graph.md) —— 62 个知识点与 65 条前置依赖边（含强度与判据）
- [references/syllabus.md](references/syllabus.md) —— 模块与知识点目录，用于核对编号

题目按知识点打标（如 `points: ["5.4"]`），这是能诊断的前提。若用户给的答卷没有知识点编号，先用题干对照 syllabus.md 判定，判不准的标「未定位」，不要硬猜。

## 第一步：换算掌握度

对每个知识点：

```
掌握度 = 该知识点所有题目的得分之和 ÷ 题目数
```

- 客观题（单选/判断）：对 1 分、错 0 分
- 操作题：按考纲三档给分 —— `1` 全部关键步骤正确，`0.5` 思路对但漏次要步骤，`0` 方法错误或未作答
- 一道题挂了多个知识点时，得分同时计入每个知识点（一题多点是常态，不要只算第一个）

分档：

| 掌握度 | 判定 | 含义 |
| --- | --- | --- |
| ≥ 0.8 | 掌握 | 不再安排补讲 |
| 0.6–0.8 | 待巩固 | 需要少量针对性练习 |
| < 0.6 | 薄弱 | 进入回溯与补测流程 |

## 第二步：回溯病根

对每个**薄弱**知识点 `B`，找它的直接前置 `A`，算拖累程度：

```
贡献度 = (0.8 − A 的掌握度) × 边强度     仅当 A 的掌握度 < 0.8
```

- 同一前置拖累多个薄弱点时，贡献度累加，按贡献度降序排名
- **A 没有作答记录时，不要给贡献度**，归入「待补测」：说明"这个点缺数据，建议先测一次再判断"
- A 的掌握度 ≥ 0.8 时贡献度为 0，说明薄弱点不在上游，问题就在 B 本身（多为概念或审题问题），此时建议补 `B` 而不必上溯
- 可以继续向上回溯一层（A 的前置），但最多两层；再往上就属于整章没学，不属于"单点病根"

这一步是整个 Skill 的核心：**结论要落到"该补哪个点"，而不是"错了哪些题"**。

## 第三步：结合错因标签

用户提供了错因标签（概念混淆 / 审题不清 / 计算失误 / 记忆不牢 / 步骤遗漏 / 参数错误 / 操作顺序错误 / 不会做）时，用它修正建议措辞：

- 同一知识点反复出现「概念混淆」「记忆不牢」→ 需要重讲概念，不是刷题
- 出现「步骤遗漏」「参数错误」「操作顺序错误」→ 需要步骤化训练与清单核对
- 出现「审题不清」→ 建议专项审题训练，与知识点掌握无关
- 出现「计算失误」→ 练速度与检查习惯

## 输出格式

用户没有指定格式时，输出如下 JSON：

```json
{
  "scope": { "name": "张三", "className": "计算机1班", "submissionCount": 4 },
  "summary": { "pointTotal": 62, "tested": 4, "weak": 3, "solid": 1, "averageMastery": 0.38 },
  "weakPoints": [
    { "id": "5.4", "name": "常用函数", "attempts": 1, "mastery": 0, "level": "薄弱" }
  ],
  "rootCauses": [
    {
      "id": "5.3",
      "name": "公式与单元格引用",
      "mastery": 0.5,
      "contrib": 0.285,
      "dragging": ["5.4"],
      "note": "常用函数依赖公式与引用语法，5.3 只有一半，先把引用方式练熟"
    }
  ],
  "needsTesting": [
    { "id": "8.4", "name": "基础查询与条件查询", "reason": "8.5 统计函数与查询的薄弱可能源于它，但该点还没有作答记录" }
  ],
  "plan": [
    "先补 5.3：相对/绝对/混合引用各 5 题，做对再练 5.4",
    "补测 8.4 基础查询后再判断 8.5 是否需要重讲",
    "7.3 分支已掌握，7.4 循环的薄弱属于自身问题，安排循环嵌套专项"
  ]
}
```

`plan` 必须可执行：给出顺序、每个点的练习量与判断标准，不要写"多练习""加强巩固"这类空话。

## 判定纪律

1. **没数据不下结论**。未测知识点一律归入 `needsTesting`，不要按"看起来像"推断掌握度。
2. **不虚构知识点编号**。所有 id 必须能在 syllabus.md 里查到。
3. **不下医学式断言**。说"这个点的题目正确率 50%，且它的前置掌握 50%"，不说"该生逻辑思维薄弱"。
4. **样本太少要提示**。某知识点只有 1 次作答时，在结论后附「样本少，仅供参考（n=1）」。
5. **全班诊断**时，先按知识点算班级平均掌握度，再单独列出"薄弱人数最多的 3 个点"，不要只报总分。
